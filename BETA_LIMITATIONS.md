# Beta limitations

- Desktop Chrome unpacked installation only. Store review, store installation and
  store-to-store updates are not verified. Development badges remain intentional.
- The current default package has no hosted account configuration. Authentication,
  email delivery, hosted multi-device concurrency, backup/restore policy, production
  alerts and actual cloud cleanup schedules remain deployment gates.
- GeeksforGeeks individual free Python/DSA articles are the supported scope.
  Layout/canonical-identity checks can reject changed pages. The latest basic live
  probe on 2026-10-26 passed Python Variables and rejected a tutorial directory;
  it did not complete an article or verify all DSA pages. Videos, quizzes and coding
  submissions are unsupported.
- Browser tracked means observed activity. Device owners can fabricate local
  records or browser evidence. Server-authoritative rewards do not independently
  prove attention or learning. There are no competitive/cash-value rewards.
- Multiple goals can be saved, but only one GeeksforGeeks goal receives new article
  tracking at a time. An article stays bound to its initial goal and cannot earn
  duplicate article credit on another goal. Tracking the same article repeatedly
  is not a supported way to earn another day.
- Current local storage supports up to 200 article checkpoints. Export and clear
  device activity from Settings when needed. This also erases local streaks/XP,
  bookmarks and unsynced submissions; a JSON export is not importable yet.
- Continue restores observed position, not skipped coverage. Resume links stay on
  this browser; there is no cross-device resume. Clearing extension/profile data,
  changing extension identity or uninstalling can remove local progress.
- A missed learning day resets the current streak. Best streak and earned milestone
  bonuses remain. Local target changes take effect at the next learning midnight;
  changing a local goal does not edit its already-copied cloud definition.
- Cloud credit uses server receipt dates. Offline or maintenance-delayed activity
  can count on a later day; unconfirmed submissions expire after seven days.
  Pausing sync preserves the queue, while signing out discards it with a warning.
- Notifications need optional permission and an awake/running browser. Quiet
  hours, snooze/deduplication, OS settings or delivery failures may suppress them.
  Native permission dialogs and OS delivery still need manual checks.
- Automated checks verify export contents and initiate downloads, but the current
  sandbox cancels actual file persistence even on a plain web page. Confirm saving
  and opening a JSON export in normal Chrome before relying on export.
- No automatic telemetry or feedback transmission is enabled. Diagnostic sharing
  is optional and manual. Do not share account/device exports as bug reports.
- This bundle records internal checks only. No participants, real-user completions,
  retention rates or consumer demand have been established by generating it.
